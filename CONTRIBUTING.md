# Як запропонувати виправлення / How to contribute

Почніть із [відкладених записів поточного набору](review-overlays/2026-10-18-sol-resolved/corpus/held-records.json.gz) (3 191) або [окремих записів бази застосунку](review-overlays/2026-10-18-sol-resolved/baseline-held-records.json.gz) (135). Файл CURRENT_EDITORIAL_FOLLOWUP.json — історична черга від 15 жовтня, а не поточний список невирішених перекладів. Також можна повідомити про іншу конкретну помилку. Перегляньте відкриті issues та [створіть issue за шаблоном](https://github.com/MityaPolianskii/ukrainian-cedict/issues/new/choose). Вкажіть ID, китайське слово, точний піньїнь, номер сегмента від 0, англійський текст, поточний український переклад і причину сумніву. Запропонована заміна бажана, але не обов’язкова. Додайте доступне публічне джерело й зазначте невпевненість та використання машинного перекладу.

Для PR зберігайте ID, китайські, англійські та джерельні поля, порядок сегментів, китайські посилання й піньїнь у дужках. Покажіть текст до та після зміни й пояснення. Виправлення мають отримати окремий overlay, синхронізовані CSV, поточні черги, лічильники й хеші. Поточний валідатор закріплює саме цей випуск: він не прийме зміненого словника без нового перевіреного baseline. Не змінюйте заморожені аудити чи очікувані хеші лише для проходження перевірки. Запускайте `python3 -B scripts/validate.py` на розпакованому ZIP без `.git`, щоб перевірити цей випуск.

Запускайте `python3 -B scripts/check_release.py` з повного checkout: обгортка перевіряє заморожений словник і новіший набір виправлень разом. Поточний стан проєкту й джерела містить [STATUS.json](STATUS.json).

Залишайте `human_validation: false` та `runtime_approved: false` у вихідній машинній чернетці; ці поля не описують доступність окремо кваліфікованих перекладів у випущеному застосунку. Критерії підтвердження перевірки людиною ще потрібно узгодити. Старі черги й карантинні примітки — історичні свідчення; чинні примітки містить лише `dictionary.json`.

Reports in English are welcome. Use the latest qualified overlay text, or identify a held record with its source universe (original corpus or separate app baseline). The 882-entry root follow-up queue is historical; it must not be added to the current held totals. Run `python3 -B scripts/check_release.py` on a complete checkout to verify both releases and current status.

Include the entry ID, exact Chinese/pinyin, zero-based segment index, English source, current Ukrainian text, reason, optional replacement and public supporting source. For PRs preserve source fields, IDs, segment order, references and bracketed pinyin. Explain before/after changes and any machine assistance. A new reviewed overlay and synchronized derived files are required for a future release. The current frozen validator verifies this exact release; do not rewrite immutable evidence or hashes merely to pass it.
